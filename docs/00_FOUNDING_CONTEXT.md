# Founding Context

Alexandria began with a simple frustration: serious AI work kept losing its thread.

Every reset meant rebuilding the same context. Every tool change risked losing the reasoning behind decisions. Every long gap made the project harder to re-enter.

The project was built to test whether ordinary markdown could preserve enough structure for humans and agents to recover together.

## The Founding Idea

The Library of Alexandria matters as a metaphor because the tragedy was not only lost books. It was lost continuity.

Alexandria is named after that problem:

- preserve context
- preserve relationships between ideas
- preserve decisions
- preserve recovery paths
- preserve understanding across time

## What Changed Through Use

The early system was more philosophical. Repeated use forced it to become more operational.

The current public proof focuses on:

- agent relay
- session recovery
- audit evidence
- public/private separation
- problem-solving visibility
- archive discipline

The founding story still matters, but the system is now judged by whether it works under imperfect use.

## The Practical Promise

A new person or agent should be able to enter the project, read the right small set of files, understand what is true now, and continue without starting over.

That is the point of Alexandria.
